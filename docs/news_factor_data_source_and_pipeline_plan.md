# 新闻因子数据源与落地路线

## 1. 现状判断

当前 `finance_news_crawler` 已聚合的快讯源，更适合做：

- 市场情绪
- 宏观冲击
- 主题热度
- 政策扰动
- 商品/指数/汇率解释

但如果目标是横截面多因子选股，单靠这些快讯还不够，因为它们的个股密度偏低，无法稳定映射到 `stock_code × date`。

## 2. 还需要补哪些信息源

### 2.1 个股公告源

这是做实体级因子的核心来源，适合中低频研究。

建议优先接入：

- 巨潮资讯网
- 上海证券交易所公告
- 深圳证券交易所公告

可用于构造：

- 业绩预告因子
- 公告情绪因子
- 并购重组因子
- 回购增持因子
- 处罚诉讼因子
- 定增融资因子

### 2.2 投资者讨论源

适合做散户情绪、关注度、舆情热度。

建议优先接入：

- 东方财富股吧
- 东方财富搜索/问董秘

可用于构造：

- 散户情绪因子
- 讨论热度因子
- 争议度因子
- 主题拥挤度因子
- 情绪反转因子

### 2.3 研报与机构观点

适合做分析师关注度、评级变化、盈利预期变化。

可用于构造：

- 分析师关注度
- 评级上调/下调因子
- 盈利预测调整因子
- 机构情绪因子

### 2.4 行业/商品/宏观专题源

适合做行业、商品、指数、汇率等品种级因子。

可用于构造：

- 产业链热度
- 供需冲击
- 政策冲击
- 库存变化影响

## 3. 三类因子如何落地

### 3.1 实体级情绪因子

目标：

- 把新闻映射到公司、行业、商品品种、指数

程序链路：

```text
新闻文本 -> 实体识别 -> 实体映射 -> 情绪打分 -> 按 stock_code + date 聚合
```

可输出字段：

```text
date | stock_code | news_count | sentiment_mean | sentiment_sum | pos_count | neg_count
```

### 3.2 事件级冲击因子

目标：

- 识别新闻属于什么事件
- 衡量事件对标的的冲击程度

建议先定义事件类型：

```text
业绩
政策
并购重组
回购增持
减持
诉讼处罚
事故停产
订单合同
产品涨价
融资定增
高管变动
海外制裁
```

程序链路：

```text
新闻文本 -> 事件分类 -> 事件权重 -> 情绪方向 -> 冲击分
```

可输出字段：

```text
date | stock_code | event_type | event_count | shock_sum | shock_max
```

### 3.3 信息环境因子

目标：

- 描述某实体或主题在某日的信息环境

核心指标：

- 热度
- 新颖度
- 分歧度
- 正负并存程度

可输出字段：

```text
date | entity | heat | novelty | dispersion | pos_neg_coexistence
```

## 4. 建议的程序结构

不要把这些逻辑全部堆进爬虫本身，建议拆成独立流水线：

```text
finance_news_crawler/
  factor_pipeline/
    entity_matcher.py
    event_classifier.py
    sentiment_scorer.py
    novelty.py
    daily_factor_builder.py
  metadata/
    stock_master.csv
    industry_map.csv
    event_keywords.json
    sentiment_lexicon.json
```

### 4.1 `entity_matcher.py`

负责把新闻文本中的公司名、简称、代码、行业、品种映射出来。

### 4.2 `event_classifier.py`

负责给新闻打事件类型标签。

### 4.3 `sentiment_scorer.py`

负责情绪打分，先可用词典规则，后续再升级 BERT。

### 4.4 `novelty.py`

负责新颖度、近似去重、与历史新闻的相似度比较。

### 4.5 `daily_factor_builder.py`

负责按交易日聚合并生成因子表。

## 5. 推荐实施顺序

### 第一步

先补实体密度高的数据源：

- 巨潮公告
- 东方财富股吧
- 东方财富搜索/问董秘

### 第二步

建立基础主表：

- `stock_master.csv`
- `industry_map.csv`

### 第三步

先做规则版因子：

- 关键词事件分类
- 词典情绪打分
- 日度聚合
- 横截面排序

### 第四步

再升级 NLP：

- Word2Vec：扩展财经近义词和主题词
- TF-IDF：提取每日热词
- BERT：做情绪分类、事件分类、实体判断
- Embedding：做新颖度和近似去重

## 6. 现在这套快讯源更适合做什么

当前 5 个快讯源最适合的方向是：

- 市场总体情绪监控
- 宏观事件冲击解释
- 主题热度追踪
- 重要消息日内聚合

如果要做真正的横截面因子研究，必须补公告、股吧、问董秘、研报等实体密度更高的数据。

## 7. 一句话结论

新闻情绪不是终点，真正能进入多因子模型的是：

```text
某个标的在某个时间窗内，经历了什么类型、什么强度、什么新颖度、什么方向、什么分歧的信息冲击
```

这也是后续所有 NLP 因子工作的主线。

## 8. 下一阶段重点：巨潮公告、股吧/雪球与金融词典体系

### 8.1 个股公告源先从巨潮资讯网开始

个股公告源不建议一开始同时接很多站点，第一阶段可以只做巨潮资讯网。

原因：

- 巨潮公告更容易落到具体上市公司
- 公告标题、公告日期、股票代码、公司简称等字段更适合结构化
- 业绩预告、并购重组、回购增持、减持、处罚诉讼等事件更适合做中低频因子
- 相比普通快讯，公告更接近公司基本面变化

后续接入巨潮时，需要重点解决：

- 如何调用公告列表接口
- 如何按日期区间分页
- 如何按股票代码或公司简称筛选
- 如何下载或解析公告正文
- 如何识别公告类型
- 如何把公告映射到 `stock_code × date`

### 8.2 股吧和雪球用于投资者情绪

股吧、雪球和公告不是同一种信息源，它们更适合衡量投资者情绪、关注度和观点分歧。

建议分工：

```text
巨潮资讯网：正式公告、公司事件、基本面冲击
东方财富股吧：散户情绪、讨论热度、舆情拥挤度
雪球：主动投资者观点、观点分歧、情绪传导
```

股吧和雪球后续可以用于构造：

- 投资者情绪因子
- 讨论热度因子
- 争议度因子
- 看多/看空分歧因子
- 主题拥挤度因子
- 舆情反转因子

需要注意的是，股吧和雪球文本噪音比公告更高，后续必须加强：

- 用户发帖去重
- 广告和灌水过滤
- 情绪极端词识别
- 股票简称歧义处理
- 同一主题反复刷屏处理

### 8.3 金融词典是后续 NLP 的底座

后续文本分析不能只依赖一个简单的“情绪词典”，而应该建立一套金融词典体系。

建议至少拆成 6 类：

#### 8.3.1 情绪词典

用于判断文本方向。

示例：

```text
利好、利空、超预期、低于预期、增长、下滑、回购、减持、违约、处罚、获批、中标、扭亏
```

#### 8.3.2 事件词典

用于识别新闻或公告属于什么事件。

示例：

```text
业绩预告、并购重组、回购、增持、减持、停产、处罚、诉讼、订单、合同、涨价、政策、制裁、违约
```

#### 8.3.3 实体词典

用于把文本映射到股票、行业、品种、指数。

示例字段：

```text
stock_code, stock_name, short_name, industry, concept, aliases
```

#### 8.3.4 强度词典

用于衡量冲击强弱。

示例：

```text
大幅、显著、严重、首次、重大、紧急、持续、突破、创历史新高、超出预期
```

#### 8.3.5 否定与转折词典

用于修正情绪方向，避免误判。

示例：

```text
不、未、无、否认、澄清、但、然而、不过、尽管、虽然
```

#### 8.3.6 主题词典

用于跟踪行业、概念和宏观主题。

示例：

```text
AI、半导体、新能源、地产、银行、黄金、原油、军工、机器人、低空经济、算力
```

### 8.4 金融词典的建设方法

词典不要一次性追求完整，建议采用“三步法”。

#### 第一步：人工种子词表

先手工做小而准的 v1 版本。

每类词典先准备 50 到 200 个高置信词即可，重点是准确，不是数量。

#### 第二步：基于语料自动扩展

用后续积累的新闻、公告、股吧、雪球文本自动扩词。

可用方法：

- TF-IDF：提取每日或每周高频主题词
- Word2Vec：寻找财经近义词和相关词
- PMI/共现：寻找经常共同出现的实体和事件词
- Embedding 相似度：扩展语义接近的词

#### 第三步：人工筛选与版本化

自动扩出来的词必须人工筛选，否则噪音会很大。

建议按版本保存：

```text
metadata/
  sentiment_lexicon_v1.json
  event_lexicon_v1.json
  entity_lexicon_v1.csv
  intensity_lexicon_v1.json
  negation_lexicon_v1.json
  topic_lexicon_v1.json
```

### 8.5 推荐开发顺序

下一阶段建议按这个顺序推进：

```text
1. 接入巨潮资讯网公告
2. 梳理东方财富股吧和雪球爬取方案
3. 建立金融词典 v1
4. 做规则版情绪打分
5. 做规则版事件分类
6. 生成 stock_code × date 的日度因子表
7. 再逐步引入 Word2Vec、TF-IDF、BERT、Embedding
```

这一阶段的核心目标不是把模型做得很复杂，而是先把“文本数据如何稳定变成因子表”这条链路跑通。
